# 岗位画像澄清 Agent 前端方案 v0

> 当前阶段：`prd-to-frontend` 阶段 2——ASCII 线框确认稿  
> 上游基线：《岗位画像澄清 Agent PRD v0》  
> 界面类型：已登录的岗位项目工作台  
> 已确认方向：A 的三栏协作结构＋C 的沉浸式对话  
> 当前不包含：官网、登录页、后台管理、后端接口和 Agent 核心实现

## 1. 设计原则

1. **对话是推进工作的方式，岗位画像才是核心业务产物。** Agent 的回答不代替岗位画像，正式画像始终固定显示在右侧。
2. **用人经理是项目发起人。** 用人经理创建岗位画像项目、提出初始业务需求并确认业务准确性；HR 加入项目后补充招聘约束并确认招聘可执行性。
3. **每个时刻只有一个主动作。** 澄清阶段为“提交回答”，画像完成后变成“提交确认”，校准阶段变成“处理校准建议”。
4. **事实状态必须可见。** 已确认、待确认、冲突、系统获取、Agent 推断不能只存在于后台。
5. **参考 GPT/Codex 的对话体验，但不复刻通用聊天产品。** 左侧是岗位项目，右侧是岗位画像和证据，不是聊天历史和通用附件栏。
6. **视觉采用字节系企业产品风格。** 使用清晰网格、高信息密度、克制圆角和蓝色主操作，禁止紫色渐变和卡片堆叠。

### 4.1 三栏职责

#### 左栏：项目与状态

- 第一层是岗位项目，不是聊天会话。
- 项目行显示岗位名、阶段和待办数量，不显示最后一句聊天内容。
- 选中项目后展示项目内导航：需求澄清、候选人校准、版本与决策。
- “创建岗位项目”始终由用人经理触发。
- HR 未加入时显示邀请入口；加入后显示头像和其待确认数量。

#### 中栏：沉浸式澄清对话

- Agent 消息默认无气泡、左对齐，减少客服机器人感。
- 用户回答使用很浅的蓝灰底或右侧短块，与 Agent 内容区分。
- Agent 每次最多提出 1—3 个高价值问题。
- 选项用于帮助取舍，但必须保留“其他，我来说明”。
- 结论更新、资料读取和失败等过程使用单行状态，不模拟冗长思考过程。
- 输入框固定在底部；可以引用资料、上传结构化简历或补充文字。

#### 右栏：岗位画像业务对象

- 默认固定显示，不随着聊天滚动消失。
- 顶部可切换“岗位画像／证据与冲突／版本”。
- 岗位画像严格分为岗位说明、人才规格和成功评分卡。
- 每个字段展示状态，点击“来源 N”打开证据抽屉并定位原文。
- 对话导致字段更新时，仅该字段浅蓝高亮 1 秒；不使用流光或渐变。
- 有关键冲突时，相关字段保持冲突状态，且发布按钮不可用。

## 5. 创建岗位画像项目

创建动作采用右侧宽抽屉，不离开工作台。目标是让用人经理用一次自然语言输入完成启动，不先填写长表单。

                                  │                                       │
                                  │ 你希望招聘什么岗位？                  │
                                  │ [产品经理___________________________] │

                                  │ │ 负责把当前交付方案做成标准产品…… │ │
                                  │ └───────────────────────────────────┘ │
                                  │                                       │
                                  │ 系统将自动获取                        │
                                  │ ✓ 组织信息  ✓ 旧 JD  ✓ 历史招聘案例  │
                                  │ ○ 招聘约束（可由 HR 加入后补充）      │

                                  │                                       │

规则：

- 项目创建人默认为当前用人经理。
- 岗位名称和初始业务需求必填；其余内容由 Agent 获取或在后续对话中补齐。
- 不把“是否新增编制、预算、职级”等 HR 信息做成阻塞项目创建的必填字段。
- 创建后直接进入 S-01 的需求澄清状态。

## 6. Sample 状态线框

### 6.1 S-01：模糊需求——默认正常状态

入口：用人经理创建项目并输入“需要一个懂 B 端的产品经理”。

界面反馈：

- 中栏先复述当前理解，并明确哪些是原始输入、哪些仍是推断。
- 每轮只追问当前最影响画像的成功结果或关键任务。
- 右栏实时形成草稿，缺失字段显示“待补充”，而不是生成通用内容。
- 主 CTA：`提交回答`。

## 7. 岗位画像确认与发布 V0

确认采用右栏中的固定检查视图，不弹出大段 AI 总结。

```text
┌───────────────────────────────────────┐
│ 提交岗位画像 V0                       │
│ 完整性检查                            │
│ ✓ 岗位说明                            │
│ ✓ 人才规格                            │
│ ✓ 成功评分卡                          │
│ ✓ Must-have 均有关联依据              │
│ ✓ 无未解决关键冲突                    │
│                                       │
│ 角色确认                              │
│ 用人经理： [确认业务准确性]            │
│ HR：       等待加入 / [提醒确认]       │
│                                       │
│ 只有两项确认完成后才能发布正式 V0。    │
│                  [暂存] [发布 V0·禁用] │
└───────────────────────────────────────┘
```

确认规则：

- 用人经理和 HR 分别确认自己的责任范围。
- Agent 的运行时 Approval 不能代替这里的业务确认。
- 若画像在一方确认后被修改，该角色的确认自动失效并说明原因。
- 双方确认完成后，唯一主 CTA 变为`发布 V0`。

## 9. 系统状态与失败回退

| 状态 | 中栏表现 | 右栏表现 | 用户动作 |
| --- | --- | --- | --- |
| 初始加载 | 显示正在读取组织、旧JD和历史案例的逐项状态 | 画像骨架＋局部加载态 | 可先补充需求，不阻塞输入 |
| 无项目 | 提示“由用人经理创建第一个岗位画像项目” | 不显示空画像卡片 | 创建岗位项目 |
| 资料缺失 | 明确说明哪个来源未获得，不由 Agent 猜测 | 对应字段标记“资料缺失” | 手动补充或稍后重试 |
| 接口失败 | 保留已获得资料和用户输入，显示失败原因摘要 | 已有画像不回滚、不清空 | 重试该来源 |
| Agent 生成失败 | 保留用户刚才的回答，不重复提交 | 画像停留在上一版本 | 重新生成 |
| 关键冲突 | 中栏展示双方来源并要求确认 | 字段标红，发布禁用 | 确认有效事实 |
| 样本不足 | 显示“样本信号”而非市场结论 | 校准建议标记低置信 | 再收集一批或维持 V0 |
| 敏感偏好 | 阻止其成为岗位标准并解释原因 | 正式画像不变 | 转交 HR 复核 |
| Session 恢复失败 | 新会话顶部概括项目当前阶段和下一动作 | 从独立项目数据层恢复画像 | 继续项目 |

## 12. 关键交互约束

1. 点击右栏字段的“来源”可打开证据抽屉；点击“定位到对话”滚动并短暂高亮原始消息。
2. 点击快捷选项只选中内容，不自动发送，避免误提交业务事实。
3. Agent 更新画像前显示明确变更摘要；关键字段变更需责任人确认。
4. 发布按钮在资料仍缺失时不一定禁用，但存在关键冲突、Must-have 无依据或双人确认不完整时必须禁用。
5. 用户切换项目时，未发送的输入暂存于当前项目，不跨岗位复用。
6. 所有可点击区域具备 hover、focus 和键盘操作状态。
7. 动效尊重 `prefers-reduced-motion`；不使用持续呼吸光、渐变流光或模拟思维链动画。

## 13. 门 2 待确认项

请在进入 React 编码前确认：

1. 是否采用上述“左侧项目／中间对话／右侧画像”的固定桌面结构。
2. 创建项目是否采用右侧抽屉，并保持“岗位名称＋初始需求”为唯一必填内容。
3. 右栏是否默认固定展开，岗位画像／证据与冲突／版本使用页签切换。
4. 校准阶段是否继续沿用同一工作台，只将中栏切换为证据矩阵和校准对话，而不另做独立系统。
5. 移动端是否只支持快速回答、查看和确认，批量简历矩阵主要在桌面端完成。
