02WHY THIS AGENT
LESS MISUNDERSTANDING

招聘真正缺的，不是更多文字。

通用模型可以快速写出“像 JD 的内容”，但无法自动证明事实从哪里来、谁有权决定，以及招聘团队能否据此执行。

A

业务语言
不是岗位定义

“找个懂 B 端的人”没有业务变化、组织缺口与成功结果，无法稳定推导 Must-have。

B

生成内容
不是正式事实

模型越流畅，越容易把猜测包装成共识。未确认信息必须停留在草稿。

C

Prompt
不是权限系统

经理、HR、候选人数据和公开 JD 的可见范围不同，真正的边界必须在服务端。

先理解意图，再决定是否执行。

Router 是一次真实的 Flash 模型调用，但它永远看不到工具。它只输出三种动作，不拥有任何业务写入能力。

05REGISTERED TOOLS
REGISTRY ≠ VISIBILITY

当前代码注册 8 个领域工具。

原来的七项能力已经增加 read_recruiting_context。注册只是 Bundle 具备能力，不代表模型在当前任务中可见。

01read_role_state

最小岗位状态读取服务端按角色与任务过滤后的字段；它不是权限控制器。

02read_recruiting_context

招聘上下文按最窄 projection 读取组织、历史澄清、漏斗或公开参考。

03update_role_identity_draft

岗位身份草稿只保存用户明确说出的岗位名称或团队。

04save_fact_draft

岗位事实草稿记录背景、原因、成功标准和约束，状态只能是 DRAFT。

05save_artifact_draft

产物草稿画像、评分卡、JD、HR Brief；已注册，当前在线任务不暴露。

06save_candidate_evidence

候选人证据保存脱敏证据批次；当前改为 Caller 整批校验后写入。

07propose_calibration_signal

校准信号提出待 HR 审核建议；当前由 Caller 持久化。

08read_version_diff

版本差异只读同类正式产物的两个授权版本。

权限来源：登录会话 + 当前 Agent Run + 业务服务鉴权；任何模型工具参数都不能自报 tenant、role 或 run 身份。

07DEFENSE IN DEPTH
PROMPT IS ONLY LAYER ONE

六道闸门，逐层收紧。

安全边界来自重复校验，而不是一句“请不要越界”。任何一层发现任务、身份或数据不一致，都应停止执行。

Prompt 分层，职责不混写。

单一事实源位于 packages/agent-spec。Router 与 Domain 使用不同 System Prompt，业务数据进入明确的不可信数据块。

ROUTER MODE
P-02 · ROUTER SYSTEM

09SIDECAR-ONLY RUNTIME
NO PRODUCT MOCK BRANCH

只有一条产品运行路径：Sidecar。

测试可以使用本地模型桩验证协议，但它不能成为产品降级回复。运行配置不存在可切换的 HARNESS_MODE。
